daplis_rtp.gui.widgets.controls module

The controls the tabs are made of, built once and used by all of them.

Four tabs choose a daughterboard, a motherboard, a firmware version and a number of timestamps. Before this module each of them built those four itself, which is how the “Full Sensor” combo boxes came to be 80 px Expanding while everyone else’s were 100 px Fixed, and how one tab came to offer a motherboard the others did not. A control that exists once cannot drift.

class daplis_rtp.gui.widgets.controls.DirectoryPicker(parent=None, caption='Data folder', title='Select Directory', tip=None)[source]

Bases: QWidget

A caption, a path, and a Browse button - one header row’s worth.

Every tab that reads data files has one of these, and on the full sensor tab there are two, which is why the shell reserves two header rows on every tab: the plot has to start at the same height whether a tab fills both or one.

A row of ‘name: value’ readings, for the second header row.

The tabs that need only one browse row put a reading here instead of leaving the row empty - which is how the top-most pixels came out of the control column, where they were costing every tab in the application a row of height.

daplis_rtp.gui.widgets.controls.float_field(parent=None, placeholder='auto')[source]

A field for one axis limit, or nothing at all.

A line edit rather than a spin box because a spin box has no way to say “unset”, and an edge left unset is one that autoscales. Accepts ‘-1.5’, ‘2e-3’, ‘10e3’; the range is deliberately the whole of float, since a photon rate and a stream length share no scale worth capping.

daplis_rtp.gui.widgets.controls.float_value(field)[source]

A field’s value as a float, or None when it is unset.

A field left empty - or holding a fragment the validator tolerated while typing, such as a lone ‘-’ or ‘e’ - means that edge should autoscale rather than break the plot.
